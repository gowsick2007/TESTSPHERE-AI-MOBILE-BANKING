What is TestSphere AI?

TestSphere AI is a custom QA DevOps engineering intelligence platform designed for mobile banking regression suites. It maps test cases, file dependency graphs, failure frequencies, and target device profiles to decide which tests to execute or safely skip during a code change commit.

Rule-Based Additive Scorer Engine

The engine calculates a deterministic risk score (0 to 100) for each test using weights defined in config.json:

Risk Score = DirectCoverage (+40)
           + DependencyRelationship (+30)
           + HistoricalFailureAssociation (+20)
           + RecentFailureRecord (+15)
           + HighRiskDeviceOS (+10)
           + SecuritySensitiveChange (+40)
           + CriticalBankingModule (+35)

If a test's final cumulative score meets or exceeds the selection threshold (50), the test is selected to RUN. Otherwise, it is safely marked as SKIP, unless a Safety Override triggers.

Safety Overrides (Mandates RUN)

Under uncertain or high-impact conditions, TestSphere enforces safety over optimization. The 7 strict rules are:

  1. RULE 1: Unknown Dependency: Triggers if dependency map is empty or changed files are missing from graph. Enforces RUN.
  2. RULE 2: Unknown Coverage: Triggers if test coverage data is missing or empty. Enforces RUN.
  3. RULE 3: Security-Critical Classification: Triggers if a test is marked security-critical in test coverage suite. Enforces RUN.
  4. RULE 4: Critical Module Altered: Triggers if changed module is Authentication, OTP, Payment, UPI, UPI, etc. Enforces RUN.
  5. RULE 5: Empty Failure Archives: Triggers if failure history registry is empty. Enforces RUN.
  6. RULE 6: Low Decision Confidence: Triggers if selection confidence level is computed as LOW. Enforces RUN.
  7. RULE 7: Rollback Override Mode: Triggers if administrators toggle the active system strategy to LEGACY_FULL_SUITE. Enforces RUN for all tests.
